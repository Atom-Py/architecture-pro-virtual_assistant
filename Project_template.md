# Проектная работа 7 спринта: RAG-бот для QuantumForge Software

## Задание 1. Исследование моделей и инфраструктуры

Цены и характеристики актуальны на 24.10.2026, источники в конце раздела.

### Заказчик и ограничения

Задачу ставит руководство QuantumForge Software. Бот нужен разработчикам, поддержке, менеджерам, аналитикам и новым сотрудникам.

Что влияет на выбор:

- В базе знаний есть документы по интеграции с SCADA-системами клиентов (ABB, Wärtsilä, энергокомпании). Это конфиденциальные данные клиентов и объектов критической инфраструктуры.
- Компания из ЕС и проходит SOC 2. Любой внешний сервис, который получает документы, становится обработчиком данных и попадает в аудит поставщиков.
- Продакшн уже в AWS (EKS + RDS), деплой через Terraform, Helm и ArgoCD.
- Документация на английском, вопросы задают и на других языках, в прототипе на русском. Нужен поиск, который находит английский текст по русскому вопросу.

В RAG найденные фрагменты документов попадают в промпт LLM, поэтому конфиденциальность в первую очередь зависит от того, где работает LLM.

### 1. Сравнение LLM

Сравниваются:

- локальные модели с Hugging Face на vLLM: Qwen3.8-27B (FP8) и gpt-oss-20b;
- OpenAI: GPT-6.1 Sol и GPT-6 Luna;
- YandexGPT Pro 5.1 и Alice AI LLM.

| Критерий | Локальные (Hugging Face) | OpenAI | YandexGPT |
| --- | --- | --- | --- |
| Качество, индекс Artificial Analysis [1] | Qwen3.8 27B: 27.6, gpt-oss-20b: 9.0 | GPT-6.1 Sol: 47.8, GPT-6 Luna: 29.9 | в рейтинге нет |
| Скорость | зависит от GPU, опубликованных замеров для своего сервера нет | медиана [1]: Sol 49 токенов/с и 3.96 с до первого токена, Luna 92 токена/с и 2.79 с | данных нет |
| Стоимость в месяц | g6e.xlarge [7]: $1 441 круглосуточно или $521 в рабочие часы (12 ч, 22 дня), от числа запросов не зависит | Sol $286, Luna $14 [2], в EU-регионе на 10% дороже [3] | Pro 5.1: 72 800 ₽, Alice AI LLM: 54 600 ₽ с НДС [4] |
| Развёртывание | GPU-узел в EKS, vLLM, обновление весов, мониторинг | API-ключ; хранение и обработка в ЕС (`eu.api.openai.com`) через отдел продаж и только с Zero Data Retention или изменённым мониторингом [3] | аккаунт Yandex Cloud, для нерезидентов оплата в USD и договор с юрлицом в Сербии или Дубае [5] |
| Данные | остаются в AWS компании | не используются для обучения, логи хранятся до 30 дней [3] | регионы Россия и Казахстан [5], запросы логируются по умолчанию [6] |

Выводы:

- OpenAI лучше по качеству и проще в запуске, но фрагменты документов с каждым запросом уходят внешнему обработчику.
- YandexGPT компании из ЕС не подходит: данные обрабатываются в России, а решения ЕС о достаточности защиты данных для России нет [18].
- Локальная Qwen3.8 27B по индексу близка к GPT-6 Luna. В RAG модель отвечает по найденным фрагментам, поэтому её собственные знания менее важны. Качество проверим на золотом наборе вопросов в задании 7.

### 2. Сравнение моделей эмбеддингов

| Критерий | Sentence-Transformers (локально) | OpenAI Embeddings |
| --- | --- | --- |
| Модели | multilingual-e5-small (118M параметров, вектор 384), base (278M, 768), large (560M, 1024), до 512 токенов, MIT [8] | text-embedding-3-small (вектор 1536), text-embedding-3-large (3072), до 8 192 токенов [9] |
| Скорость создания индекса | для e5 замеров нет; модель того же размера paraphrase-multilingual-MiniLM-L12-v2 кодирует 7 500 предложений/с на V100 [10]; на CPU квантование ONNX/OpenVINO ускоряет в 1.9-2.8 раза [11]; на нашем корпусе замерим в задании 3 | упирается в лимиты API: 1 млн токенов в минуту на уровне Build, 30 млн токенов не быстрее 30 минут; Batch API в 2 раза дешевле, но выполняется до 24 часов [9] |
| Качество поиска | MIRACL nDCG@10: small 60.8, base 62.3, large 66.5 [8]; русские вопросы к английским текстам (MKQA Recall@100): large 76.8 [12] | MIRACL: 3-large 54.9 [12]; MKQA по русскому: 3-large 72.0 [12] |
| Стоимость | бесплатно, считается на серверах бота | весь корпус: 3-small $0.60, 3-large $3.90 [2] |
| Данные | остаются внутри | тексты уходят в OpenAI |

Выводы:

- Цена не важна, индексация всего корпуса в OpenAI стоит меньше доллара.
- По многоязычному поиску e5 не хуже OpenAI.
- Выбор: intfloat/multilingual-e5-small. Это самая лёгкая многоязычная модель, которая принимает чанк в 300 токенов целиком (paraphrase-multilingual-MiniLM-L12-v2 обрезает текст до 128 токенов). Если поиск окажется слабым, можно перейти на base или large.

### 3. Сравнение ChromaDB и FAISS

| Критерий | FAISS | ChromaDB |
| --- | --- | --- |
| Что это | библиотека Meta на C++ с обёрткой для Python, MIT, версия 1.15.1 [13] | база данных, Apache-2.0, версия 1.5.9; встроенный режим, сервер в Docker, Chroma Cloud [14] |
| Скорость поиска | SIFT 1M при точности от 0.9: HNSW 3 920 запросов/с, IVF 1 422 [16]; на 100 000 векторов хватает точного Flat | 4-5 мс на запрос для 0.7-15 млн векторов [14]; в режиме сервера добавляется сетевой вызов |
| Скорость индексации | Flat и IVF строятся за секунды, HNSW на 1 млн векторов от 700 до 2 500 с [16] | HNSW дополняется пачками по 50-250 векторов [14] |
| Метаданные и фильтры | нет, только числовые id; LangChain хранит тексты в pickle и фильтрует после поиска [15][17] | фильтры по метаданным и полнотекстовый поиск [14] |
| Обновление | `remove_ids` для Flat и IVF, одновременные запись и поиск не поддерживаются [15] | добавление, изменение и удаление через API [14] |
| Внедрение и поддержка | `pip install faiss-cpu`, индекс в двух файлах; `load_local` требует `allow_dangerous_deserialization`, поэтому загружать можно только свои файлы [17] | встроенный режим так же прост; сервер нужно отдельно защищать (встроенной аутентификации нет с версии 1.0), бэкапить и мониторить [14] |
| Стоимость владения | работает внутри процесса бота, 100 000 x 384 x 4 байта = 154 МБ памяти | свой сервер от 2 ГБ RAM; Chroma Cloud от $250 в месяц, регионы aws-us-east-1 и gcp-europe-west1 [14] |

Выводы: на 100 000 чанков обе базы ищут за миллисекунды. FAISS не требует отдельного сервиса. Chroma понадобится, если появятся фильтры по правам доступа или запись из нескольких экземпляров бота.

### Варианты

| Критерий | А. OpenAI | Б. YandexGPT | В. Свои модели в AWS | Г. Гибрид |
| --- | --- | --- | --- | --- |
| Состав | GPT-6.1 Sol, text-embedding-3-small, FAISS | YandexGPT Pro 5.1, эмбеддинги Yandex, FAISS | Qwen3.8-27B на vLLM, multilingual-e5-small, FAISS | multilingual-e5-small и FAISS в AWS, GPT-6.1 Sol через `eu.api.openai.com` с Zero Data Retention |
| Качество | 47.8 | нет данных | 27.6 | 47.8 |
| В месяц | около $290 | около 72 800 ₽ | от $521 до $1 441 | около $315 |
| Данные | уходят в OpenAI | обрабатываются в России | остаются в AWS | найденные фрагменты уходят в OpenAI |
| Внедрение | проще всего | новый провайдер, договор вне ЕС | GPU-узел, MLOps | согласование с OpenAI |

Выбираю вариант В:

1. Документы клиентов не уходят внешним обработчикам, это проще для SOC 2 и GDPR.
2. Нагрузка небольшая, одного GPU-узла хватает, стоимость фиксированная.
3. Всё работает на текущем стеке: EKS, Terraform, Helm, ArgoCD.
4. vLLM даёт OpenAI-совместимый API, поэтому переход на вариант Г при нехватке качества сводится к смене адреса и модели в настройках.

### Векторная БД для бота

FAISS. На нашем объёме поиск занимает миллисекунды, индекс хранится в двух файлах рядом с ботом, отдельный сервис с аутентификацией и бэкапами не нужен. Индекс легко пересобирать по расписанию и подменять целиком (задание 6). Отсутствие фильтров по метаданным и одновременной записи одному боту не мешает.

Остальной стек прототипа: эмбеддинги intfloat/multilingual-e5-small, LLM через OpenAI-совместимый API, интерфейс в Telegram.
